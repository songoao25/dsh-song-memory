# 项目决策：dsh-song-memory v2.0 —— 引擎升级 + 界面重构（对齐 mnemon）

## 背景（2026-08-18 连续反馈链）

1. 用户发现原始记录"显示不全、记录不在重点" → 完成两级整理 + 噪音闸门（v1.5.2 已完成）。
2. 用户发现记忆被主 Agent 工作汇报污染 → 调研后按行业方案对齐（P0/P1 已完成）：AI 侧改"整理时吸收"、
   AI_FACT_RE 白名单化、存量迁移（v1.6 已完成）。
3. 用户发现**跨项目内容被误注入此对话**（全局单文件 memory.md 所有项目共享）+ 修复过程摘要变短
   → 诊断：需按项目隔离记忆（行业做法：全局偏好 + 项目级隔离）。
4. 用户提出调研 [mnemon](https://github.com/mnemon-dev/mnemon)（Go 写的 LLM-supervised 持久记忆引擎）
   → 调研结论：官方已有 DSH 集成插件 [dsh-mnemon](https://github.com/omdsh-dev/dsh-mnemon)
   （MIT，v0.2.9，三层记忆系统：运行时记忆/项目文档/记忆空间，9 种 Provider，自带完整 WebUI）。

## 用户拍板（2026-08-18）

1. **引擎选型**：接入 dsh-mnemon（解决跨项目隔离 + 图召回），song-memory 保留自研界面层。
2. **最终形态（用户自定义）**：用户曾用 dsh-mnemon"用得舒服"，但**它的图形页面太复杂、不知道从哪下手**。
   用户明确要求：**"用我的理念去重构它的页面。把它的图形页面移植过来，然后简化一下，但不丢失任何功能。"**
3. **确认**："保留 dsh-mnemon 全部功能（记忆空间/运行时记忆/文档/写入门控/备份/导入导出等），
   但用苹果 HIG 理念重做界面：简化信息层级、让每个功能一目了然。功能不丢，但更好用。"
4. 记忆摘要恢复：从备份找回个人记忆并合并（已完成，见 memory.md「你的偏好与要求」节）。

## 目标（v2.0）

- **引擎**：dsh-mnemon（真实存储/隔离/召回/写入门控能力）。
- **界面**：用苹果 HIG 理念重做 dsh-mnemon 的页面——简化层级、大白话术语、功能全保留。
- **入口**：song-memory 现有界面（记忆摘要/原始记录/整理）+ dsh-mnemon 功能页整合为统一、简洁的体验。
