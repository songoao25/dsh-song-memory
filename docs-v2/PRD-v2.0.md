# PRD：dsh-song-memory v2.0（记忆引擎升级 + 界面重构）

> 版本：v2.0 草案（待用户确认）
> 关联文档：docs/product-definition-v2.0.md（产品定义）、docs/DECISION-v2.0-mnemon.md（决策档案）、docs/dsh-mnemon-FUNCTION-MAP.md（14 模块功能全貌）
> 本文是给工程师的"施工图"：每条需求有唯一编号 + Given-When-Then 验收标准。开发前有疑问先查本文件；本文件未覆盖的歧义点，见文末「开发前待澄清清单」，不得擅自假设。

## 1. 背景与目标

### 1.1 背景

dsh-song-memory v1.x 用全局单文件（memory.md/notes.md）保存记忆，出现三个问题：

1. **跨项目内容误注入**：所有项目的对话混在一个文件里，A 项目的内容会注入 B 项目的对话（2026-08-18 用户实测踩到，且修复过程中丢失过记忆摘要）。
2. **界面太复杂**：调研选定 dsh-mnemon（Go 引擎 + 官方 DSH 插件，MIT/Apache-2.0 开源）作为新引擎，能力很强（14 个功能模块、三层记忆系统、9 种存储服务），但它的页面有 14 个模块、最深 4~5 层、满屏术语（记忆体/沉淀/召回/Provider/存储域…），用户"不知道从哪下手"。
3. **记忆质量**：AI 工作汇报污染记忆、摘要像流水账。

### 1.2 目标

v2.0 = **接入 dsh-mnemon 引擎（解决隔离与图召回）+ 用苹果 HIG 理念重做界面**，实现：

- 记忆按项目隔离（mnemon named stores / workspace scope 原生能力），A 项目内容绝不注入 B 项目；
- 界面"默认简单、高级折叠、术语全白话"——功能一个不少（14 模块全保留），但一看就懂、一用就会；
- 写入门控生效：AI 工作汇报不自动进记忆，用户明确存入的内容可靠保留；
- 旧数据（v1.x 草稿箱/记忆摘要）先导出备份再切换，升级不丢数据。

### 1.3 用户已拍板的 6 项功能决策（D1–D6，PRD 全部落实，可追溯）

| 决策 | 内容 | 落实到 |
|---|---|---|
| D1 | 一级导航用「记忆 / 常用小抄 / 项目文档 / 运行状态」四个大白话标签（替代记忆体/运行时/档案/状态） | FR-3 |
| D2 | 创建记忆仓库只填名字+说明，引擎自动"智能 + 本地优先"，高级项折叠 | FR-4 |
| D3 | 「存入记忆」一键存入，AI 自动判断值不值得存/存哪/查重 | FR-5 |
| D4 | 检索只保留一个搜索框（智能模式默认，关键词/基础模式折叠） | FR-6 |
| D5 | 图谱/实体收进"高级"（默认不显示，点「查看关系图」才展开） | FR-10 |
| D6 | 旧数据（v1.x 草稿箱/摘要）先导出备份再切换，保证不丢 | FR-12 |

## 2. 目标用户

- 长期用 DSH 与 AI 协作的个人开发者（用户本人即典型用户，非技术背景）；
- 在多个项目间切换工作，需要 AI 记住偏好、项目决定与长期目标，但**不想维护任何数据库、不想读任何术语**；
- 曾因记忆工具"功能强但页面复杂"而放弃深入使用的人。

## 3. 功能需求（FR-1 ~ FR-12）

> 编号规则：FR-x。优先级 = MoSCoW（Must 缺失即版本失败；Should 本轮做、顺序靠后但不做不算完成"功能零丢失"）。每条验收标准均为可自动/人工执行的检查项。
> 术语约定：本 PRD 使用的"记忆仓库 / 常用小抄 / 项目文档 / 运行状态 / 存入记忆 / 检索 / 存储服务"均为用户可见新术语，与 dsh-mnemon 旧术语的映射见附录 A。

### FR-1 引擎接入：5 分钟可起步

- **描述**：完成 mnemon 引擎（Go 二进制）+ dsh-mnemon 插件（dsh plugin add）的安装与启用；新用户按 README 指引，从零到"能存第一条记忆"不超过 5 分钟。安装动作只做一次，此后插件随 DSH 启动自动可用。
- **优先级**：Must（一切功能的前提）
- **验收标准**：
  - Given 一台干净的 DSH 环境（未安装 mnemon 引擎与 dsh-mnemon 插件），When 按 README 的安装指引操作，Then 5 分钟内完成：引擎安装成功 + 插件启用成功 + 「运行状态」页显示引擎"健康（绿）"，全程无需用户修改任何配置文件。
  - Given 插件已启用但引擎未启动，When 打开「记忆」页或对话页，Then 页面不白屏、不抛错，显示中文引导（"记忆引擎未启动，点这里修复"），点击后能自动拉起引擎或给出可执行的修复步骤。
  - Given 全新环境引擎就绪，When 打开「记忆」页，Then 当前项目自动获得可用记忆仓库（自动创建或一句话引导创建），用户无需理解"存储域/Provider"等概念即可开始存入。
  - Given 安装过程失败（如网络中断），When 安装向导返回错误，Then 错误信息为中文、指出失败步骤与重试/替代方案，且已完成的步骤不重复执行。

---

### FR-2 记忆按项目隔离（跨项目零污染）

- **描述**：每个 DSH 项目拥有独立的记忆仓库（mnemon named stores / workspace scope）。A 项目的记忆内容不注入 B 项目的对话、不进入 B 项目的检索结果。这是 v2.0 相对 v1.x 的核心修复。
- **优先级**：Must（用户核心痛点）
- **验收标准**：
  - Given 在项目 A 中存入标记性内容"项目A专用标记：香蕉派42"，When 在项目 B 的对话中发起检索/召回（智能模式），Then 返回结果中不含"香蕉派42"的任何内容。
  - Given 项目 A 与项目 B 均有记忆仓库且内容不同，When 在项目 B 打开「记忆」页，Then 默认展示项目 B 的仓库；项目 A 的仓库不默认注入项目 B 的对话上下文。
  - Given 用户在项目 B 明确切换到项目 A 的仓库查看，When 查看完成，Then 回到项目 B 对话后，注入内容仍是项目 B 的，不残留项目 A 内容。
  - Given 两个项目存在同名记忆条目，When 分别在各自项目检索，Then 各返回本项目的版本，绝不串仓（自动化测试：A/B 项目各存 5 条标记内容，交叉检索命中数必须为 0）。

### FR-3 四大白话导航

- **描述**：记忆工作台一级导航固定为四个大白话标签：**记忆 / 常用小抄 / 项目文档 / 运行状态**（对应旧术语：记忆体→记忆 / 运行时→常用小抄 / 档案→项目文档 / 状态→运行状态）。用户可见文本中禁止出现旧术语（见附录 A 对照表）。
- **优先级**：Must（界面重做核心，D1）
- **验收标准**：
  - Given 用户打开记忆工作台，When 查看一级导航，Then 恰有「记忆 / 常用小抄 / 项目文档 / 运行状态」四个标签，且整页用户可见文本中不出现"记忆体、沉淀、召回、Provider、存储域、档案、运行时"等旧术语（对照附录 A 全表扫描）。
  - Given 用户点击任一标签，When 切换页面，Then 内容正确切换，且浏览器返回键可回退到上一标签（每层均有明确回退路径，导航层级不超过 2 层）。
  - Given 当前激活标签，When 查看，Then 有清晰的选中态（苹果 HIG：选中状态视觉可辨、触碰目标不小于 44pt、标签不因窗口变窄而错位或重叠）。

### FR-4 记忆仓库管理（创建只填两项，高级项折叠）

- **描述**：原"记忆体（spaces）"重做。创建仓库**只填「名字 + 说明」两个必填字段**，引擎自动采用默认配置：本地优先存储 + 智能写入策略（AI 自动判断值不值得存）。激活/停用开关、删除等原 dsh-mnemon 全部操作保留，但高级项（存储服务选择、自动存入策略、高级参数）折叠在「高级」中，默认不展开。
- **优先级**：Must（"开关一个仓库"是无教程三操作之一，D2）
- **验收标准**：
  - Given 用户点「新建记忆仓库」，When 表单出现，Then 默认可见字段只有「名字」「说明」两项，无任何技术选项；填写后点「创建」，Then 仓库创建成功、默认启用、默认"智能 + 本地优先"，用户未做任何技术选择。
  - Given 用户点「新建记忆仓库」，When 展开「高级」，Then 出现与原 dsh-mnemon 等同的完整选项（存储服务/Provider、自动存入策略、高级参数），无一项缺失。
  - Given 仓库列表页，When 查看每个仓库，Then 每个仓库有一目了然的「开关」（启用/停用）与「删除」操作；开关切换即时生效。
  - Given 用户停用仓库 W，When 在当前项目发起检索，Then 默认结果不含 W 的内容（或结果中明确标注"已停用"）；When 重新启用 W，Then 内容恢复可检索。
  - Given 用户点「删除仓库」，When 确认对话框出现，Then 必须二次确认并明确提示"删除后该仓库的记忆无法找回（可先备份）"；取消则不删除。
  - Given 仓库创建时名字为空或与现有仓库重名，When 提交，Then 表单给出中文错误提示并阻止创建。

### FR-5 一键存入记忆（AI 自动判断：值不值 / 存哪 / 查重）

- **描述**：原"沉淀（remember）"重做。对话内提供「存入记忆」按钮，用户也可直接说"帮我记住…"。触发后 AI 自动完成三件事：①判断值不值得存；②决定存入当前项目的哪个仓库；③查重（与已有记忆实质相同则不重复存）。交互默认**一键直存 + 结果轻提示**，仅在 AI 判定"低价值"或"重复"时弹出确认。
- **优先级**：Must（"存一条"是无教程三操作之一，D3）
- **验收标准**：
  - Given 用户在对话中点击「存入记忆」按钮或说"帮我记住：我喜欢简洁界面"，When 提交，Then 内容完整写入当前项目最合适的仓库，并给出轻提示"已存入记忆 ✓（存入：当前项目 · 自动选择）"，正文含"我喜欢简洁界面"。
  - Given 用户点击「存入记忆」但内容是明显一次性闲聊（如"今天好累"），When AI 判定低价值，Then 弹出确认"这条可能不值得长期记忆，仍要存入吗？"，用户确认才写入，取消则不写入。
  - Given 用户存入与已有记忆实质相同的内容，When AI 检测到重复，Then 提示"这条与已有记忆重复：<预览>。更新 / 跳过？"，不产生重复条目；选"更新"则覆盖旧值，选"跳过"则不做任何写入。
  - Given 当前项目存在多个记忆仓库，When 用户存入，Then AI 自动选择最合适的仓库并在提示中注明去向；用户可在提示中改选其他仓库。
  - Given 用户说"帮我记住"但未说明内容范围，When 提交，Then AI 以当前对话上下文为准提取要记住的内容并回显给用户确认后写入（不存空内容）。

### FR-6 检索（一个搜索框，结果卡片）

- **描述**：原"检索（search）"重做。检索页**只有一个搜索框**，默认「智能模式」（语义召回，支持自然语言提问），返回**结果卡片**：每条卡片显示内容预览、来源（哪个项目/仓库）、相关度标签（相关 / 一般 / 忘记）。关键词/基础模式折叠在「高级」里，默认不展开。
- **优先级**：Must（"找一条"是无教程三操作之一，D4）
- **验收标准**：
  - Given 检索页，When 页面加载，Then 只显示一个搜索框（无模式切换、无筛选条件平铺）；输入自然语言问题（如"上次定的命名规则是什么"）回车，Then 返回结果卡片列表，每张卡片含：内容预览、来源（项目名/仓库名）、相关度标签（相关/一般/忘记）。
  - Given 用户点某张结果卡片，When 展开，Then 显示完整内容与上下文，并提供「回到对话注入」按钮（可将该记忆注入当前对话）。
  - Given 用户需要精确匹配，When 展开「高级」并切换关键词模式，Then 可按关键词精确检索，支持原 dsh-mnemon 检索的全部筛选能力。
  - Given 检索无结果，When 提交搜索，Then 显示友好空态（"没找到。换个说法试试，或展开高级用关键词模式"），不报错、不显示技术细节。
  - Given 检索请求发出，When 用户在结果返回前离开页面，Then 不产生报错或残留加载态（下次进入可正常使用）。

### FR-7 常用小抄（原"运行时"重做）

- **描述**：原"运行时（runtime）"重做，改名「常用小抄」。提供小抄条目的**增删改查**，每条小抄分两类：**关于我**（个人偏好）或 **关于项目**（项目规则）。小抄内容以紧凑形式注入每轮对话，用户可在「本回合记忆」入口核对当前注入了什么。
- **优先级**：Should（本轮做，保留原运行时能力；开发顺序排在核心体验之后）
- **验收标准**：
  - Given 用户打开「常用小抄」页，When 点「新增」，Then 表单默认只有「内容」「分类（关于我 / 关于项目）」两项；保存后条目出现在对应分类下。
  - Given 小抄列表页，When 查看，Then 支持按分类筛选与关键词搜索。
  - Given 用户编辑或删除一条小抄，When 保存，Then 修改即时生效，且后续新对话的注入内容同步更新（注入内容 = 最新小抄）。
  - Given 小抄有内容，When 新开一轮对话，Then 该轮对话的「本回合记忆」面板可见小抄内容；小抄为空时面板显示"暂无小抄"而非报错。
  - Given 小抄内容包含敏感信息（如密钥），When 保存，Then 系统给出提示"敏感信息不建议写入小抄（每轮都会注入对话）"，用户确认后才保存。

### FR-8 项目文档（原"档案"重做）

- **描述**：原"档案（documents）"重做，改名「项目文档」。提供文档的**新建 / 编辑 / 搜索 / 归档**。新建文档默认只有「标题 + 正文」两个字段；高级项（元数据、标签、关联实体等）折叠在「高级」中。
- **优先级**：Should（本轮做，保留原档案能力；开发顺序在核心体验之后）
- **验收标准**：
  - Given 用户打开「项目文档」页，When 点「新建文档」，Then 默认表单只有「标题」「正文」两个字段，无任何技术选项；保存后文档出现在列表。
  - Given 文档详情页，When 用户编辑标题或正文并保存，Then 内容更新，列表同步刷新。
  - Given 文档列表页，When 输入关键词搜索，Then 按标题 + 正文内容匹配返回结果，无结果时显示空态提示。
  - Given 用户对某文档点「归档」，When 确认，Then 文档移出默认列表（可在"已归档"筛选下找回），不删除内容。
  - Given 用户点「新建文档」，When 展开「高级」，Then 出现原 dsh-mnemon 文档模块的全部高级选项（元数据/标签/关联实体等），无一项缺失。

### FR-9 运行状态（健康可视化 + 版本检查）

- **描述**：原"状态（status）"+"版本/Headless"两模块合并为一个「运行状态」页：三个健康指标（引擎 / 存储 / 插件连接）用**红黄绿状态灯 + 一句话中文说明**呈现；版本区显示当前引擎与插件版本，提供「检查更新」。
- **优先级**：Should（本轮做，功能简单但用户依赖其判断"是否一切正常"）
- **验收标准**：
  - Given 用户打开「运行状态」页，When 引擎/存储/连接全部正常，Then 三个指标均为绿色 + 汇总"一切正常"。
  - Given 任一指标异常（引擎未启动 / 存储不可写 / 插件未连接），When 查看该指标，Then 状态灯为黄色（警告）或红色（故障），并附中文原因与可执行修复动作（如"引擎未启动 → 点这里启动"），修复动作可一键执行或给出可复制命令。
  - Given 用户打开「运行状态」页，When 查看版本区，Then 显示 mnemon 引擎版本号与 dsh-mnemon 插件版本号，以及「检查更新」按钮；有新版时提示可升级，点击后走升级流程。
  - Given 引擎处于故障状态，When 用户打开「记忆 / 常用小抄 / 项目文档」任一页，Then 页面不白屏，顶部显示横幅引导"记忆引擎异常，去运行状态查看"，点击直达「运行状态」页。

### FR-10 高级设置区（存储服务合并 / 备份恢复 / 图谱实体）

- **描述**：原「配置（config）」与「沉淀策略（strategy）」中重复的存储配置合并为**一处**「存储服务」设置（消除"同一批难懂字段分散两处"的问题）。「备份恢复」默认**一键全量**（无需勾选组件）。「图谱 + 实体」默认不显示，点「查看关系图」才展开。
- **优先级**：Must（备份恢复=数据安全；存储合并=消除重复；图谱折叠=决策 D5）
- **验收标准**：
  - **存储服务（合并）**：Given 用户打开「高级设置 → 存储服务」，When 查看，Then 本地存储与云端存储（原 Provider）的全部选项和自动存入策略（原 strategy）在同一页面可配置；全应用范围内该配置**只有这一处入口**（自动测试：全界面扫描，无第二处同名配置入口）。
  - **备份（一键全量）**：Given 用户点「备份」，When 进入备份页，Then 默认即"全量备份"（无需勾选任何组件），点击「立即备份」生成带时间戳的备份文件并可下载；备份过程中显示进度，完成后显示文件位置。
  - **恢复**：Given 用户有备份文件，When 点「恢复」，Then 默认全量恢复；恢复前弹出明确警告"恢复将覆盖当前全部记忆，确定继续？"，确认后才执行；恢复成功后提示重启/刷新生效。
  - **图谱/实体（默认折叠）**：Given 用户打开「记忆」页默认视图，When 查看，Then 页面不显示图谱、实体、节点/边等任何关系图内容；页面上可见一个「查看关系图」入口，When 点击，Then 展开图谱视图（节点/边/检查器），实体列表可从图谱视图内进入。
  - Given 用户从未点过「查看关系图」，When 完成任意其他操作，Then 图谱/实体界面不主动弹出、不干扰主流程。

### FR-11 功能零丢失（14 模块全部可达）

- **优先级**：Must（用户明确要求"功能全保留"，是验收硬项）
- **验收标准**：
  - Given 重做后的完整界面，When 按附录 B 的 14 模块清单逐项核对，Then 14/14 全部可从新界面到达（含"记忆仓库高级折叠、图谱展开、高级设置"内的入口），无一项消失。
  - Given 用户拿着旧 dsh-mnemon 的某个功能名（如"沉淀策略"），When 在帮助/术语对照表中查询，Then 能查到"沉淀策略 → 高级设置 → 存储服务 → 自动存入策略"这类明确映射。
  - Given 迁移验证阶段，When 用旧界面功能操作清单（14 项：看状态、看运行时、建档案、建记忆体、看图谱、检索、看实体、沉淀、配策略、内容浏览、备份、配置、对话内按钮、版本检查）逐项在新界面执行，Then 14/14 项均能完成同等操作。
  - Given 任何旧功能被折叠/展开，When 核对，Then 折叠只是隐藏入口，不是移除功能（展开后能力与原版一致，无阉割）。

### FR-12 旧数据迁移（v1.x 先备份再切换）

- **描述**：从 v1.x（memory.md/notes.md 全局单文件）切换到 v2.0 引擎**之前**，系统必须提供「导出 v1.x 记忆」流程，将草稿箱 + 记忆摘要导出为备份文件；切换后提供恢复路径，保证升级不丢数据。未备份不允许切换。
- **优先级**：Must（数据安全，D6）
- **验收标准**：
  - Given 用户升级 v2.0 前，When 打开迁移入口（升级向导或设置内「旧数据迁移」），Then 提供「导出 v1.x 记忆」一键操作，生成包含**草稿箱全部内容 + 记忆摘要全文**的备份文件（含时间戳，用户可下载/复制到安全位置）。
  - Given 备份文件已生成，When 用户执行引擎切换，Then 切换过程中**不执行任何删除动作**；v1.x 数据文件保持原样，切换失败可回退。
  - Given 用户未生成备份就尝试执行切换，When 触发切换，Then 系统强制拦截并提示"请先导出 v1.x 记忆备份"，提供「去备份」按钮；不允许跳过备份直接切换。
  - Given 用户已完成切换并持有备份文件，When 需要找回旧数据，Then 提供「从备份恢复」路径，旧数据可被读取查看（恢复目标仓库的策略见「开发前待澄清清单」Q1）。
  - Given 切换完成后，When 用户打开 v2.0 界面，Then 新引擎正常运行，且界面提示"旧数据已备份，可随时在高级设置中恢复"，不出现数据丢失提示。

## 4. 非功能需求（NFR）

### 4.1 安全（NFR-S）

- **NFR-S1 本地优先**：默认配置下，全部记忆数据只保存在本机（mnemon 本地存储），**不向任何新第三方服务上传数据**；使用云端存储必须是用户显式选择的高级操作。
  - 验收：Given 全新安装（未做任何配置），When 运行 24 小时并抓取网络请求，Then 除 DSH 既有必需通信外，无任何发送记忆内容的第三方请求；Given 用户选择云端存储，When 启用，Then 界面明确提示数据将离开本机，需用户确认。
- **NFR-S2 密钥不入记忆**：密钥、口令、token 等敏感信息不因自动写入进入记忆仓库；用户明确确认后仍可存（由用户负责）。
  - 验收：Given 对话中出现形如 API 密钥/口令的文本，When AI 自动判断写入，Then 默认拦截并提示"这看起来是敏感信息，不建议存入记忆"，用户明确确认才写入。
- **NFR-S3 写入门控生效**：AI 工作汇报/系统输出不自动进入记忆；用户明确存入的内容可靠保留。
  - 验收：Given 主 Agent 在对话中输出工作汇报（如"已完成 X，下一步 Y"），When 回合结束，Then 汇报内容不自动写入任何记忆仓库；Given 用户点「存入记忆」，When 提交，Then 内容可靠写入且可在检索中找到（自动化样例：10 条汇报全部拦截入库数=0；10 条明确存入全部可检索=10/10）。
- **NFR-S4 删除可逆有底线**：删除/覆盖类操作（删仓库、恢复覆盖）必须二次确认；备份文件不因升级流程被自动删除。

### 4.2 性能（NFR-P）

- **NFR-P1 存入响应**：用户点「存入记忆」到看到结果提示，本地 AI 判定场景 ≤ 3 秒。
  - 验收：Given 本地环境（CPU ≥ 4 核、内存 ≥ 8G），When 连续执行 20 次「存入记忆」，Then 单次判定到提示 ≤ 3 秒（P95）。
- **NFR-P2 检索响应**：智能模式输入问题到结果卡片 ≤ 5 秒；关键词模式 ≤ 2 秒。
  - 验收：Given 仓库含 ≥ 500 条记忆，When 提交智能检索，Then 结果返回 ≤ 5 秒（P95）；关键词模式 ≤ 2 秒（P95）。
- **NFR-P3 对话注入不拖慢**：启用记忆注入后，每轮对话开始的时间开销不显著增加（≤ 1 秒）。
  - 验收：Given 记忆功能启用与停用两种状态，When 各发起 10 轮对话，Then 启用状态的回合开始延迟相比停用状态增加 ≤ 1 秒（P95）。

### 4.3 兼容（NFR-C）

- **NFR-C1 DSH web 模式**：全部界面功能（记忆/常用小抄/项目文档/运行状态/高级设置）在 DSH web 界面可用。
  - 验收：Given DSH web 模式，When 逐项执行 FR-1~FR-12 验收用例，Then 全部通过。
- **NFR-C2 DSH headless 模式（无浏览器）**：核心记忆能力可用——存入记忆、检索、小抄查看可通过命令行/最小交互完成；界面类功能可安全降级（显示"请在 web 界面使用"），不崩溃。
  - 验收：Given DSH headless 模式，When 执行"存入一条记忆、检索一条记忆、查看小抄"，Then 三条命令均成功且数据与 web 模式互通；Given 打开界面类功能，Then 显示降级提示而非报错。
- **NFR-C3 版本兼容**：mnemon 引擎与 dsh-mnemon 插件版本更新不破坏现有记忆数据；升级前自动提示备份。
  - 验收：Given 插件有小版本升级，When 升级完成，Then 既有记忆可正常检索，无数据迁移错误。

### 4.4 可维护（NFR-M）

- **NFR-M1 术语对照表落地**：新增 `docs/UI-TERMS.md`，维护"旧术语 → 新白话术语"完整对照表（以附录 A 为基础扩充）；全界面用户可见文本禁用旧术语，代码评审时按对照表校验。
  - 验收：Given 评审任何界面改动，When 用 `docs/UI-TERMS.md` 扫描新增文案，Then 无旧术语漏网；Given 用户可见字符串，When 检索旧术语关键词，Then 界面无命中（README/帮助文档除外）。
- **NFR-M2 界面遵循苹果 HIG**：导航层级 ≤ 2 层、触碰目标 ≥ 44pt、每层可回退、状态可见、术语一致（界面开发按 apple-hig skill 规范执行并在评审时核对）。
- **NFR-M3 可观测**：运行状态页的每个健康指标有明确的检测逻辑与日志；问题可定位（引擎/存储/连接任一异常能在日志中找到原因）。

## 5. 非目标（本版明确不做）

1. **不做 OpenViking 等外部服务器方案**：mnemon 纯本地即可满足需求，不引入服务器部署。
2. **不重写 mnemon 引擎本身**：引擎用官方（Go 引擎 + dsh-mnemon 插件），本项目只做界面层与集成层。
3. **不做多设备云同步**：mnemon 本地优先，多设备同步后续版本评估。
4. **不保留 v1.x 自研存储链路**：memory.md/notes.md 全局单文件方案退役（数据可备份导出，见 FR-12），不在 v2.0 中继续维护该链路。
5. **不新增 14 模块之外的新功能模块**：本版只重做界面与接入引擎，不发明新能力。
