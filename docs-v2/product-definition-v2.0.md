# 产品定义：dsh-song-memory v2.0（记忆引擎升级 + 界面重构）

> 状态：草案（待用户确认）
> 关联决策：docs/DECISION-v2.0-mnemon.md

## 一句话定位

为长期使用 DSH 的个人用户，提供一套**"引擎最强、界面最简单"**的跨对话记忆系统：底层用 mnemon 图结构引擎（跨项目隔离、AI 智能判断写入、跨工具通用），界面用苹果 HIG 理念重做——功能一个不少，但一看就懂、一用就会。

## 要解决的问题（v1.x 遗留 + 用户新痛点）

1. **跨项目内容误注入**：v1.x 用全局单文件 memory.md，所有项目的对话混在一起，A 项目的内容会注入 B 项目对话 → mnemon 的"记忆仓库隔离"原生解决。
2. **界面太复杂**：dsh-mnemon 能力很强（用户曾用着舒服），但它的页面有 14 个功能模块、最深 4~5 层、满屏术语（记忆体/沉淀/召回/Provider/存储域…），普通用户不知道怎么下手 → 用用户的设计理念重做界面：默认简单、高级折叠、术语全白话。
3. **记忆质量**：AI 工作汇报污染、摘要像流水账 → mnemon 的 LLM 监督写入 + 图结构召回从架构上解决。

## 核心使用场景

1. 用户在每个项目里正常干活，记忆自动按项目隔离——A 项目的事不会出现在 B 项目。
2. 用户想记点什么：对话里点「存入记忆」或说"帮我记住…"，AI 判断后存入对应项目的记忆仓库。
3. 用户想找记忆：问一句，相关记忆被召回；看到的是干净的结果卡片。
4. 用户想管理：打开记忆页面，看到的是"记忆 / 常用小抄 / 项目文档 / 运行状态"四个大白话标签，每个功能都能看懂。

## 本轮范围（in）

- **引擎接入**：安装 mnemon（brew/go install）+ dsh-mnemon 插件（dsh plugin add）。
- **界面重做**：把 dsh-mnemon 的 14 个功能模块全部保留，但按用户理念重新组织：
  - 一级导航 4 项大白话：**记忆 / 常用小抄 / 项目文档 / 运行状态**；
  - 术语全白话（记忆体→记忆仓库、沉淀→存入记忆、召回→检索、Provider→存储服务…）；
  - 高频操作平铺（存入记忆、检索、仓库开关、看小抄），高级配置（存储服务、备份、图谱）收进设置折叠；
  - 默认简单：创建记忆仓库只需填名字+说明，其余智能默认。
- **隔离验证**：确认两个项目对话互不污染（named stores / workspace scope）。

## 本轮不做（out）

- 不做 OpenViking 等外部服务器方案（mnemon 纯本地即可满足）。
- 不重写 mnemon 引擎本身（引擎用官方，我们只做界面层）。
- 不做多设备云同步（mnemon 本地优先，后续评估）。
- 不保留 v1.x 的自研存储链路（notes.md/memory.md 全局单文件方案退役；数据可备份导出）。

## 做成的标准（成功指标）

- 记忆按项目隔离：A 项目对话中注入的记忆不含 B 项目内容。
- 界面：普通用户打开后无需教程即可完成"存入一条记忆、找到一条记忆、开关一个仓库"三个操作。
- 功能零丢失：dsh-mnemon 原 14 个功能模块在重做后全部可用（可进高级设置找到）。
- 写入门控生效：AI 工作汇报不会自动进记忆；用户明确存入的内容可靠保留。
- 旧数据可迁移：v1.x 的记忆可导出备份，不因升级丢失。
